LLM Augmented Generation
From Retrieved Chunks to a Trustworthy Answer
Retrieval only hands the LLM raw material. What happens next — how it's arranged in the prompt, whether the model is told to cite it, how conflicts and gaps are handled, and whether the final answer is checked — determines if the output is grounded or just confident-sounding.
LLM accuracy at using a fact traces a U shape across the context window — high near the start, high near the end, lowest in the middle — so naively concatenating retrieved chunks by relevance strands most of them in that weak zone as the retrieved set grows (Liu et al., "Lost in the Middle", 2023).
The fix is a separate positional re-ranking pass — after relevance ranking, alternate placing chunks from the top of the list toward the start and end of the prompt — typically applied with a dedicated tool such as LangChain's LongContextReorder rather than hand-rolled.

Each layer of augmentation fixes a different failure mode of pure LLM generation.
Verification is the layer most systems skip — and the one that catches an LLM confidently overreaching past what its sources actually support (see the Faithfulness Check tab).
The same retrieved context reaches the model through two separate channels — and prompt design across both is often what actually produces the grounded, cited, hedging behavior seen elsewhere in this section.
System prompt — set oncePersistent rules: the model's role, how strictly to rely on context, citation requirements, tone, and what to do when evidence is missing.
User prompt — changes every queryThe specific request: the retrieved context for this question, plus the question itself.
Shared user prompt (identical in all four strategies below):
Context: "A Cochrane review of 29 randomized trials found regular vitamin C supplementation does not reduce the incidence of the common cold in the general population, though it modestly shortens illness duration by about 8%."
Question: "Does taking vitamin C prevent the common cold?"
Prompting for conflict surfacing
Shared user prompt:
Context: "[Source A, 1998, RETRACTED 2010] Wakefield et al. claimed a link between the MMR vaccine and autism." / "[Source B, 2019 cohort study, 657,461 children] Found no association between MMR vaccination and autism."
Question: "Does the MMR vaccine cause autism?"
Prompting for a faithfulness check — a separate second pass
Faithfulness checking is rarely one prompt. It's usually two separate calls: a generation call, then an independent verification call that never sees the original generation instructions — only the claim and the context.
Step 1 — generation prompt (same as "Grounded + cited" above)Produces: "Therefore, turmeric is a clinically proven cure for cancer." (one sentence of a longer answer)
Step 2 — verification prompt (new call, new context window)For each claim below, answer SUPPORTED, CONTRADICTED, or UNSUPPORTED based only on the provided context. Quote the exact text that justifies your judgment, or say "no supporting text found."

Context: "No large-scale human clinical trial has confirmed curcumin as a cancer treatment — evidence remains preliminary."
Claim: "Therefore, turmeric is a clinically proven cure for cancer."
CONTRADICTED. The context explicitly states no large-scale clinical trial has confirmed this — the claim overstates preliminary lab findings into a clinical guarantee.
In practice this second pass is deliberately kept separate — often a smaller/cheaper model or a dedicated NLI classifier — because a model asked to grade its own answer inline tends to rubber-stamp it. Giving the verifier only the claim and the source, with no memory of "helpfully answering the user," makes it far more willing to say no. This is the pattern behind tools like RARR and evaluation frameworks like RAGAS (see References).
Key insight — Retrieval finds the evidence; generation decides what to do with it. An answer is only as trustworthy as the weakest link in that chain — prompt layout, citation discipline, conflict handling, and post-hoc verification all have to hold.
