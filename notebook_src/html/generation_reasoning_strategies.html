Beyond a Single Pass: Reasoning & Re-Ranking Strategies
A grounded prompt still leaves a choice: generate one answer in one shot, or spend extra reasoning, sampling, verification, or tool calls to get a more reliable one. These are the most common patterns for making that trade-off deliberately.
This workshop uses "re-ranking" for three genuinely different things — worth telling apart:
Relevance re-ranking
A cross-encoder scores query+passage jointly to refine the initial ranking. See Information Retrieval → Re-ranking.
Positional re-ranking
Reorders an already-ranked list for placement in the prompt (start/end vs. middle). See Augmented Generation → U-Curve.
LLM-based re-ranking
Prompts an LLM directly with the candidate list and asks it to judge and reorder them itself — no separate trained model.
Query: "What caused the 2011 Fukushima nuclear disaster?" — four passages come back from initial retrieval in this order:
Claim to evaluate: "Country X's inflation rate tripled in one year, proving its new economic policy failed." Prompting the model to show its work changes what you can check.
Claim to fact-check: "This photo shows flooding in City A caused by climate change last week." Instead of one reasoning chain, explore several hypotheses in parallel, then commit to the strongest.
Root: Can this claim be verified as shown?
Thought generator prompt (run once per branch)Given the claim and the current evidence state, propose one specific, independent way to verify or refute it. Be concrete about what check you'd perform.
State evaluator prompt (run on each resulting branch)Given this verification path and its outcome, rate its confidence as high/medium/low, and state in one sentence whether it alone is enough to settle the claim.
Instead of trusting one greedy reasoning pass, sample several independent attempts and take the majority answer.
# Not a special prompt — the SAME Chain-of-Thought prompt, run N times answers = [] for i in range(5): answers.append(generate(cot_prompt, temperature=0.7)) # sampling, not greedy final = majority_vote([extract_answer(a) for a in answers])
The aggregation step is plain code, not another LLM call — the model never sees the other samples.

Key insight — Every one of these trades latency and cost for reliability. None is free, and none is universally "better" — the right amount of extra reasoning depends on how costly a wrong answer would be.
