Information Extraction
Validating & Verifying Extracted Information
Extraction is never perfect. Before a triple enters the knowledge base, production pipelines run it through checks like these — most of them just another prompt, but a differently-shaped one than extraction itself.
Ontology: Types Person · Organisation · Location · Study  |  Relations WORKS_AT[Person→Organisation] · AUTHORED[Person→Study] · LOCATED_IN[Organisation→Location]. Every candidate triple gets checked against this before it's allowed in.
Source: "Dr. Amara Nwosu, based at the University of Lagos, authored a new water-safety study." Each candidate triple is checked against the source text it supposedly came from.
Instead of checking triples one at a time, reconstruct a description from the triples alone, then compare it back to the original source with embedding similarity. Low similarity means something got lost in extraction — the same back-translation check used in this workshop's Part 2 hands-on.
Cosine similarity
Run the same extraction prompt twice — sampled independently, temperature > 0 — and keep only the triples both runs agree on. This is Self-Consistency applied to extraction instead of generation: no new prompt, just the extraction prompt run twice and reconciled in code.

Before inserting a new triple, check it against what the knowledge base already believes. Not every clash is a contradiction — some are just the world changing.
Existing (2020): (Alice, WORKS_AT, Acme Corp)
New candidate (2024): (Alice, WORKS_AT, Globex Inc)
UPDATE, not a contradiction — different timestamps on the same relation type usually mean the fact changed (a job change), not that one extraction is wrong. Without the dates, a naive check would flag this as conflicting and block both facts.
This is exactly why the Common Pitfalls tab warns against missing temporal modelling — contradiction-checking without valid_from/valid_to timestamps can't tell "the world changed" apart from "the extractor made a mistake".
The checks above are signals, not a single verdict — a real pipeline combines them into one decision per triple. Click a triple to see how its checks combine.
Key insight — None of these checks are exotic — most are just another prompt, shaped to interrogate rather than extract. The discipline is running them at all, on every triple, before it becomes a fact the rest of the system trusts.
