Getting the Right Chunk: Methods for Information Retrieval
Embedding search is only one retrieval strategy among several. Real systems combine lexical matching, semantic search, graph traversal, re-ranking, and query rewriting — because each method fails differently, and their failures rarely overlap.
Sparse retrieval (BM25/TF-IDF) matches exact tokens via an inverted index. Dense retrieval matches meaning via embeddings. Pick a query to see which wins — and why.
Neither method alone covers both failure modes, so production systems run both and merge the ranked lists — commonly with Reciprocal Rank Fusion: score = 1/(60 + sparse_rank) + 1/(60 + dense_rank).
Notice the winner: a document that was only decent (rank 2) on both lists outranks documents that were #1 on just one list. Fusion rewards consistent relevance over a single lucky match.
Query: "Who leads the organization that funded the water study Dr. Amara Nwosu published?" Step through the hops — vector search alone typically stalls after hop 1.
Query: "does eating sugar cause hyperactivity in children". Stage 1 retrieves cheaply by keyword/vector overlap; Stage 2 re-scores the same candidates by reading query and passage together — much slower, so it only runs on the small shortlist.

Questions and answers are often phrased so differently that even a good embedding model places them far apart. These techniques transform the query before it ever hits the index.
Key insight — There is no single best retrieval method — only trade-offs between exactness, semantic reach, latency, and cost. Production RAG systems layer several of these techniques rather than betting everything on one.
